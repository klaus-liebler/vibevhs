# 2026-11-17 – Diagnose 502 Bad Gateway nach Deploy (nur lesend)

Anlass: Klaus meldet nach frischem Deploy „502 Bad Gateway“ unter /vibevhs.

## Befehl 1 (lesend)

```
ssh liebler 'systemctl status vibevhs --no-pager -l | head -30; echo ---; journalctl -u vibevhs --no-pager -n 80 -o cat; echo ---; ss -ltnp 2>/dev/null | grep -E ":5080\b" || echo "5080 nicht belegt"'
```

Ausgabe (gekürzt):

```
Active: activating (start) … restart counter is at 11
[11:11:06 FTL] Datenbankschema veraltet (/var/lib/vibevhs/vibevhs.db: Version unbekannt, erwartet 25E4825DE6CA6F61).
  Bitte die Datenbankdatei löschen oder beiseitelegen und die Anwendung neu starten …
vibevhs.service: Main process exited, code=exited, status=2/INVALIDARGUMENT
(wiederholt sich alle ~8 s)
5080 nicht belegt
```

## Befund

Die neue Version (Normalisierung, Schema per EnsureCreated + Schemainfo-Prüfsumme) trifft auf die Datenbankdatei
der Vorversion (noch ohne `Schemainfo` → „Version unbekannt“). Der Start bricht wie vorgesehen ab, systemd startet
in Schleife neu, Kestrel lauscht nie auf 127.0.0.1:5080 → nginx liefert 502.

## Vorgeschlagene Behebung (ändernd – erst nach Klaus' Go)

Alte Datei (samt -wal/-shm) beiseitelegen, Dienst neu starten; die Anwendung baut die DB aus Start-/Demodaten neu auf.

```
ssh -t liebler 'set -e; sudo systemctl stop vibevhs; ts=$(date +%Y%m%d-%H%M%S); \
  sudo mkdir -p /var/lib/vibevhs/beiseite; \
  for f in /var/lib/vibevhs/vibevhs.db /var/lib/vibevhs/vibevhs.db-wal /var/lib/vibevhs/vibevhs.db-shm; do \
    [ -e "$f" ] && sudo mv "$f" "/var/lib/vibevhs/beiseite/$(basename "$f").$ts"; done; \
  sudo systemctl start vibevhs; sleep 15; systemctl is-active vibevhs; \
  curl -fsS http://127.0.0.1:5080/vibevhs/gesund; echo'
```

Rückweg: Dienst stoppen, Dateien aus `beiseite/` zurückbewegen (startet dann aber wieder nicht mit dieser Version).
